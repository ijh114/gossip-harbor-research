## 원작 근거와 웹 재구성

원작 `Beginning1`은 메인 장면 진입 후 CG 또는 시작 비디오를 실행하고 `InitVideoFinished`를 기다린다. `Beginning2`는 intro/fire intro 타임라인(또는 서버 설정에 따른 생략), HUD 강조, 게임 모드 변경을 거친다. 웹의 두 안내문·배경 선택·350/850ms 전환 시간은 자체 재구성이다. 두 화면을 넘겼다고 원작 CG·타임라인을 재생했다고 기록하지 않는다. 기존 논리 모델은 보드 진입에서 두 진입 노드를 완료하며 그대로 유지했다.

과제는 시작 때 충분한 골드를 확인하되 차감하지 않고, 타임라인 완료 때 비용·보상·다음 과제를 확정한다. 웹도 이 순서를 유지한다. 보상 창에서는 이미 지급된 결과를 표시하며 닫기·이어 하기에서 다시 지급하지 않는다. 과제 도중 재화를 외부 실험으로 바꾸면 확정 시 도메인이 다시 검사한다.

`MainTaskConfig`의 이름·영역·비용은 실제 장식 명령을 증명하지 않는다. 실제 명령은 `DynamicConfig.Timeline.<prefix>.Timeline_<prefix>`에 의존한다. 이전 파일명 검색에서 놓친 번들 내부 자료를 회수했고 첫60과제는 동봉 명령을 사용한다. 과제 화면의 대사는 **동봉 발췌**, 배경은 **참고 캡처·3D 미복원**으로 구분한다. 공간 시연 3종도 동일 가구의 디자인 3종이라고 표시하지 않는다. 전후 카메라는 일치하지 않는다.

## 검증

직전 화면 연결의 자동 검사 269개 통과 기록이다. 현재 확장 검증은 COMPLETION-1-2-5-6.md를 참조한다. 신규 8개는 초기 동선과 첫 주문, 중단/재개, 타이틀 체류 시 자동 확정 취소, 보상 창 복원과 중복 방지, 공간 선택의 경제 비간섭, 효과음 opt-in, 잘못된 화면 상태와 소리 대응 경계를 검사한다. 별도 앱 통합 검사는 실제 버튼 이벤트·대화상자 포커스·탭 합성·새 게임 백업을 확인한다. 기존 순수 모델의 자연 진행·소스 해시 검사는 유지했다. DOM 검사는 실제 브라우저 시각 검수나 원작 실행 결과가 아니다.

핵심 파일은 `screen-flow.mjs`(상태/경계), `screen-controller.mjs`(전환/타이머/소리), `game-scenes.mjs`/`game-scenes.css`(장면), 기존 `play-controller.mjs`의 도메인 연결이다. 단일 저장에 보상과 장면 완료를 함께 기록하며, 여러 탭 동시 편집·서버 동기화는 기존 미지원 범위다.
