# 맵·NPC 자산 분석과 출시 제작 초안

분석일: 2026-11-03. 기준: Gossip Harbor 4.10.5 APK와 해당 카탈로그에서 기존에 확보한 리소스. 페이지: `#world-assets`. 원작 실행·계정 접속·현재 서비스/최초 출시 규모 확인은 포함하지 않는다.

맵은 실제3D Mesh/재질/Transform과 카메라를 사용한다. 맵의 전신 인물은 주로2D Spine이다. 입체적인 그림 스타일과 Unity의 MeshRenderer 존재만으로 인물까지3D 모델이라고 결론 내리지 않는다. 지붕 표본의 실제 정점은 세 축에 걸쳐 있으며 원본 오브젝트와 OBJ 출력 해시를 대조했다. 카메라 투영 파생은 원작 shader/조명 재현과 구분한다.

Mesh의 raw-byte SHA 중복 제거는 이름·직렬화 필드가 다른 동일 기하를 합치지 않는다. 반대로944개 FBX 경로가 모든 독립 모델/소품 디자인을 완전하게 대표한다고 보장하지 않는다. 발주는 디자인 베이스·상태 프리팹·배치 인스턴스를 나눠야 한다.

## NPC·초상·애니메이션

| 표현 범위 | 확인한 수량 | 중복/변형 처리 |
| --- | --- | --- |

| 동물 역할 | 4프리팹 | Buster/Coconut/Zorkee3종. Zorkeerelaxed는 변형 |

| 전신 모션 | 888항목 | 움직이는887 + 길이0 Buster_idle 셋업 포즈1. 시작/반복/종료는 각각 한 항목 |

| CG 모션 | 41항목 | NPC 전신888개와 별도 |

식당 손님 중 Amala/Norman/Riley는 전신 역할에도 존재한다. Celia/Lily/Lucy를 추가하면 이름 기준 맵 인물의 합집합은30종이다. 이는 분석자 분류이며 이벤트/초상에만 등장하는 인물을 포함한 게임 전체 인원이나 원작 최초 출시 인원으로 쓰지 않는다.

전신 모션 이름의 접미사 분포는 begin221 / loop225 / end225 / idle42 / 그 외175다. `Role.Action`은 track0의 애니메이션 이름과 loop 인자를 받아 재생한다. 이름만으로 begin→loop→end를 자동 실행한다고 단정하지 않는다. `ActionList`는 지연값이 있는 비반복 행동을 큐에 넣고 완료 콜백 수를 센다. 좌표/크기는 부모 Transform, 좌우 방향은 Spine Transform의Y축180° 회전으로 처리한다. 좌우 반전 때문에 모든 애니메이션을2배로 발주할 필요는 없다.

`Customer`는 상체/하체 SkeletonAnimation을 각각 초기화하고 좌석 부모와 방향별 위치 오프셋을 적용한다. 따라서 서 있는 전신·앉은 표현·대사 초상·주문 초상을 한 “캐릭터1개” 납품으로 뭉치면 안 된다. 분리 부위의 골격 공유 여부와 고유 제작물 수를 함께 명시한다.

## 신규 게임 제작 범위 비교

다음은 승인 전 제안이다. 원작의 기본 과제에 연결된 Area1–3의 비초기 슬롯 키는49개여서3구역/50슬롯을 공간 규모의 참고로 삼았다. 지역별 슬롯 수는 일정하지 않으며 과제1개=모델1개가 아니다. 원작 Area1/2 역할의 고유 인물은11명이므로 새 시나리오를8명으로 압축하는 출시안과 같은 등장군을 유지하는 안은 다르다.

| 항목 | MVP | 소프트론칭 | 출시형 초안 |
| --- | ---: | ---: | ---: |
| 맵 구역 / 슬롯 | 1 / 6 | 2 / 24 | 3 / 50 |
| 장식 선택 슬롯(각3외형) | 3 | 12 | 25 |
| 완성 외형 | 12 | 48 | 100 |
| 초기+완성 상태 프리팹 | 18 | 72 | 150 |
| 지형 모듈 | 1 | 2 | 3 |
| 재사용 환경 모델 베이스 | 21 | 44 | 61 |
| 고유 인물 / 동물 | 3 / 1 | 6 / 1 | 8 / 2 |
| 작업/의상 변형 리그 | 1 | 1 | 3 |
| 앉은 손님 전용 리그 | 1 | 2 | 3 |
| 전신+손님 리그 | 6 | 10 | 16 |
| 전신 모션 소계 | 31 | 74 | 126 |
| 손님 모션 | 3 | 6 | 9 |

| 주문 초상 상태 | 12 | 24 | 32 |

출시형61개 모델 베이스는 건물9 + 가구/소품40 + 자연물12다. 지형3모듈은 별도다. 이 키트의 재사용과 배치/재질 변형으로50슬롯의100개 완성 외형을 구성한다. 초기50개는 공용 오염/파손/공사 레이어를 우선 재사용한다. 상태 프리팹150개를 별도 모델150개로 발주하지 않는다. 같은 디자인 베이스의 변형은 실제 재질/기하 변경 범위에 따라 검토한다.

출시형 모션은 사람8×12 + 스토리16 + 동물2×4 + 작업/의상3×2 + 손님3×3 =135항목이다. 전신만 만들면13리그/126모션이며 손님 표현을 포함하면16리그/135모션이다. 손님은 같은 인물의 별도 좌석용 골격을 공유하는 상체·하체6컴포넌트를 가정한다. 대사/주문 초상을 Spine으로 제작한다면 UI용 골격 수를 추가 확정해야 한다.

공통 인물 모션12항목의 예시는 기본 대기, 보행, 대화 반복, 기쁨 시작/반복/종료, 슬픔 시작/반복/종료, 분노, 놀람, 지시다. 모든 인물에게 기계적으로 복사하지 말고 시나리오별 행동표에서 삭제/추가한다. 장면 수·대사 수·CG 컷 수·시즌 유지 기간은 콘텐츠 기획 후 별도로 산정한다.

패스1시즌·앨범1권·보드형 대표 이벤트1종은 기존43행 요청서에 있다. 이 문서의 수량을 해당 리소스 전체 수량에 중복 합산하지 않는다. 대표 이벤트를3D 탐험형으로 바꾸거나 이벤트 전용 인물을 도입하면 환경/리그/모션을 추가 산정해야 한다.

## 납품·검수와 공유

- 환경: 편집 가능한 DCC 원본, Unity용 FBX, 텍스처/재질 매핑, 피벗/모듈 연결 규칙, 슬롯ID→상태→참조 관계.
- 인물/동물: 레이어 원본, Spine project/atlas/texture, 합의한 버전, 소품/표정 슬롯, 방향 반전, 접지, 루프/종료, 중단/복귀와 mix 규칙.
- UI 초상: 대사/주문 프레임과 상태 목록, 원화 재사용 범위, 별도 출력 그림인지 Spine 상태인지 명시.
- 맵 연출: 재사용 연출 계열, 트리거/종료/스킵/입력 잠금, 입자와 카메라/음향 연결. 객체 수와 연출 종류 수를 구분.
- 해상도/폴리곤/아틀라스/압축/메모리/드로콜은 대상 카메라·기기에서 측정 후 확정. 원작의 치수/본 수를 복사해 성능 예산으로 쓰지 않는다.

웹 계산기는 별도 localStorage 초안을 사용하며 기존43행 요청서를 덮어쓰지 않는다. 잘못된 수량은 계산/내보내기를 막는다. 요청서는 Markdown/CSV/JSON으로 내보내며 승인 전임을 명시한다. 원본 게임의 FBX/전체 골격/전체 코드/번들은 게시하지 않는다.
