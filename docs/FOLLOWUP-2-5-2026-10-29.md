# 2–5번 후속 작업 · 2026-10-29

> **상위 완료 판정 정정:** 이번 문서는 일부 하위 구현의 변경 기록이다. 기존2~5번 전체는 모두 부분 완료다. 전체 범위·고정ID·종료 기준은 [전체 작업 장부](MASTER-CHECKLIST.md)를 기준으로 읽는다.

요청한 순서대로 BM 시간순 실험 → 웹 플레이 확장 → 시각 자료 도감 → 성장·재화 검증을 진행했다. 기존 APK 근거·캡처와 이번 웹 모델 실행을 구분한다. 원작의 모든 동작·운영값·연출이 동일하게 검증됐다는 의미는 아니다.

## 2. BM 시간순 실험

- `#bm-validation`에 3개 명시 연구 시나리오, 27개 사건, JSON 편집·실행·내보내기, 사건 전후 상태와 상품/그룹/쿨다운 그래프를 추가했다.
- 기존 상점·오퍼 모델을 호출하며 별도 상태 기계를 만들지 않았다. APK Lua 20개 출처와 웹 코드 8개 출처를 연결했다.
- 기존 관측 자료의 자동 재등장·만료 확인 수는 증가시키지 않았다. 신규 원작 실행·구매·지급은 없다.

정적 조건과 현재 웹 모델의 차이 6개를 표시한다: 상품 만료의 동등 시각, 일별 횟수 초기화 시점, config 변경 판정, 번들 창 닫기의 후속 오퍼, EnergyGift 구매 성공 처리·회수·SKU 회전, 무료 충전이 있을 때 후속 오퍼용 비용 계산. 미지원 구매 사건은 보상을 지급하지 않는다. 이 차이를 숨기려고 기존 핵심 모델을 수정하지 않았다.

## 3. 웹 플레이 확장

- 추가 안내 10종을 두 저장 bank로 플레이에 연결했다. bank 전환·저장/재접속·완료 이력 보존, 강한 안내 중 입력 허용 목록, ×8 안내 재접속 종료를 연결했다.
- 활동·창 상태가 필요한 안내에는 명시 연구 입력과 사건 버튼을 제공한다. 자연 진행에서 10개 모두 자동 발동했다고 계산하지 않는다. 남은 87개 ID의 활동·서버·원작 장면 맥락은 별도다.
- 생성기 공장 6대상·23조각의 동봉 점수 규칙을 연결했다. 메인 보드/보관함의 실제 UID 소비 → 점수 전환 → 임계값 보상 → 닫힘 반환이 한 저장 변경으로 반영된다.
- 서버 활성화·6종 해금이 미확인이면 상태도 미확인이다. 연구용 해금 가정은 명시적으로 선택해야 한다. 보유하지 않은 조각을 지급하지 않는다.
- 중복 입고/보상, 낡은 UID, 가득 찬 지급 큐, 손상 필드, 실패 시 원자성 및 복구 백업을 검사했다.

공장 거미줄 자동 교환·추가 보상, 원작 LateInit/LoginFinished 자동 호출, 원작 비행/슬라이더/0.5초 입력 잠금은 미구현이다. 웹 입력 허용 목록은 원작 마스크 형상과 좌표 검증을 대신하지 않는다.

## 4. 시각 자료·위키

- 퍼즐 아래 `#factory-reference` 공장 시각 도감을 추가했다. 기존에 확보한 6대상·23조각 PNG 29종의 모습·점수·출처를 보여준다.
- 대상 선택과 10단계 입고/점수/보상/반환 시연, 이전/다음/재생/정지, 메인 저장과 분리된 시연 상태를 제공한다. 900ms 간격은 웹 시연 속도다.
- 확보 장부를 17항목·49출처로 갱신했다. 이번에 새로 복구한 원작 자산은 0개다.
- 113개 영상 메타데이터(분석 대상 게임 영상110개)와 제작 자료 노트를 검색했다. 공장/보관함 직접 태그 후보는 0개였고, 선택 상자의 `orders-inventory` 태그는 공장 근거에서 제외했다.

이는 메타데이터 검색 결과다. 이번 추가 공장 원본 프레임 육안 검수는 0개이며, 공장 화면이 전체 녹화에 없다는 뜻이 아니다. 웹 시연을 실제 녹화/GIF로 표시하지 않는다. 원본 전체 영상·APK·Lua·번들은 게시하지 않는다.
