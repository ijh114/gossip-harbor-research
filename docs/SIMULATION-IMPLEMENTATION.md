> 이 문서는 해당 작업 시점의 구현·검수 기록 또는 당시 설계다. **고정 ID와 현재 완료 판정은 [전체 작업 장부](MASTER-CHECKLIST.md)를 기준으로 읽는다.** 과거 수치·완료 표현으로 현재 상위 작업 전체가 완료됐다고 판정하지 않는다.

> 이 문서는 2026-10-28 초기 구현 계획을 보존한 이력입니다. 복수/랜덤 주문·보관함·생산 보정·자연 버블은 이후 구현했습니다. 현재 상태와 남은 일은 [최신 대응표](GAMEPLAY-PARITY-VALIDATION.md)와 [후속 상태](FOLLOWUP-STATUS.md)를 기준으로 읽습니다.

# 웹 시뮬레이션 후속 구현 순서

사용자가 전체 체크리스트의 남은 작업을 추천 순서로 진행하도록 요청했다. 기존 vanilla ES modules·Pretendard·녹색 연구 UI와 GitHub/Cloudflare 배포를 유지한다. LDPlayer 조작·분석은 재개하지 않는다.

1. **소스 기반 보드**: 실제 TypeID·MergedType·생성기의 고정 소진 풀·충전 설정·7×9 초기 상태를 최소 투영으로 가져온다. 생성기 보정·서버 교체·튜토리얼 우회는 별도 미구현 범위로 표시한다.
2. **주문·성장·BM 연결**: 내장 고정 주문과 기본 가격, 초반 맵 퀘스트의 기본 비용/보상을 연결한다. 에너지 부족에서 충전창과 오퍼 판정으로 진입하되 서버 후보·임계치는 명시적인 실험값이다. 실제 결제/광고 연결은 하지 않는다.
3. **저장·복귀**: 연구 실험 상태만 localStorage에 저장한다. 설정 revision·schema·타입/수치·크기를 검증하고 실패한 저장을 삭제하지 않는다. RNG·Type별 소진 풀·쿨다운·주문·퀘스트 상태를 보존한다. 최대7일 오프라인 경과 처리는 웹 정책이다.
4. **화면 통합**: 생성→합성→고정 주문→골드→퀘스트→에너지 부족/BM의 단일 흐름을 조작한다. 기존 흐름 시연은 유지하고 소스 기반 실험을 별도 모드로 제공한다. 원본 이미지가 있는 타입만 해당 Sprite를 쓰며, 없는 타입은 이름/ID로 표시한다.
5. **검증·게시**: 고정 풀 보존/리셋, 실패 시 자원 불소모, 덮개/인접 해제, 주문/퀘스트 단발 지급, 충전창 닫기 분기, 저장 무결성·오프라인 중복 적용 방지를 검사한다. 브라우저 연결이 되면 시각/키보드/모바일 검수 후 동일 소스를 두 호스트에 게시한다.

이 변경으로 원작 전체 재현·서버 개인화·모든 이벤트·완성 Unity 게임이 완료되는 것은 아니다. 근거가 없는 운영값은 사용자 실험 입력 또는 명시적 가정으로 분리한다. 다음 단계는 재현 가능한 추가 기믹/이벤트의 범위를 넓히고 Unity Editor/씬·신규 콘텐츠 작업으로 연결하는 것이다.
