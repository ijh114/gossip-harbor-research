# 가십하버 난이도·레벨 디자인 분석

2026-11-05 · APK4.10.5 및 같은 카탈로그에서 기존 확보한 복원 자료 기준. 웹: `#level-design`. 데이터: `src/data/level-design-study.json`. 원작 계정 실행·현재 서버 배정·유저 행동 지표는 이번 조사에 포함하지 않는다.

## 기존 자료와 이번 범위

기존 `#difficulty`에는 합성/시간/공간 압력, 기본 주문 필터와 주요 규칙이 있었다. `#growth-validation`에는 무보충 모델의 seed42 Lv26·210과제·714주문과 Lv21·150과제의3seed 비교가 있었다. 전체300레벨을 실제 원작으로 검증한 분석은 없었다.

이번에는 확보 자료의 다음 모집단을 전수 집계하고 서로 연결했다.

| --- | ---: | --- |
| 계정 성장 | 300행·정상 승급299회 | 배열 인덱스·도달XP·비용·보상 의미 분석 |

복원 Lua 설정306개와 파싱 테이블 JSON289개는 서로 다른 집합이다. JSON파일290개 중 `manifest.json`은 테이블이 아니다. 공통287·Lua만19·JSON테이블만2를 보존했다. 파싱되지 않은 장애물10개는 원문을 추가 확인했다. 이 범위를 전체103개 활동 디렉터리의 모든 운영 난이도 완료로 확대하지 않는다.

## 하나의 레벨표로 설명할 수 없는 구조

메인 게임은 같은 보드에서 생성·합성을 반복한다. 주문 골드로 스토리 과제를 수행하고, 과제XP로 계정이 성장해 기능·새 공급 경로·주문 후보가 열린다. 아이템 합성 단계, 주문 난이도 단계, 일일 누적DiffScore, 계정XP, 스토리day, 이벤트level은 서로 다른 변수다.

설계상 핵심 루프는 `생성/합성 → 주문 → 골드 → 과제 → XP/공간 변화 → 해금/승급 보상 → 주문·생성 경로 확장`이다. 활동 보상은 이 루프에 카드팩·패스 점수·이벤트 재화 등을 병렬로 붙인다. 따라서 계정레벨이 같은 두 유저도 재고·생성기·활동·도구·진행 주문이 다르면 필요한 작업량이 달라진다.

## 계정 성장 곡선

`LevelModel`은 현재 레벨의 배열행을 소비해 다음 레벨로 이동한다. Lv300 도달에는1–299행 합계 **75,660XP**가 필요하다. 300번째 행의 cost300·보상은 최대레벨에서 정상 승급으로 소비하지 않는다.

85번째 행의 원본 `level` 필드는75다. 클라이언트는 배열인덱스85로 조회하므로 원본 필드와 실제 인덱스를 모두 보존한다. 선언필드를 기준으로 재정렬하면 잘못된 곡선이 된다.

초반에는30/45/60/75XP 등으로 오르지만, Lv74–195의122개 전이는255XP이고 Lv216–299의84개 전이는300XP다. 후반 난이도가 계속 증가한다는 설명을 XP 비용 하나에 의존할 수 없다. 아이템/생성 경로·주문 단계·동시 재고·스토리 골드 비용이 함께 작동한다.

보관함·상점·버블의 내장 기본 개방은 각각 계정Lv2/3/4다. 승급행의 보상은 해당 레벨에 처음 도착할 때의 보상과 한 단계 어긋날 수 있으므로 ‘현재 행을 소비해 다음 레벨로 갈 때 지급’으로 읽는다.

## 스토리 비용과 XP

기본4,277과제는 모두 **15XP**다. 기본 골드 비용 총합은 **1,587,762G**, 과제당16–480G, 중앙값410G다. 첫480G는 day120의 `120_4`다. day1은7과제/185G, day209는18과제/8,370G로 day합이 가장 크다. day합은 개별 비용과 과제수를 함께 반영하며 실제 플레이 일수가 아니다.

전체 과제XP64,155만 더하는 산술 예시는 Lv261+195XP다. 보드XP 등 다른 획득원을 제외한 계산이므로 실제 달성 가능 레벨·유저상한이 아니다.

실제 과제비용은 `ceil(기본비용 × 최근스토리배율 × taskGoldControlRatio)`이며 현재 과제에 저장된 비용을 재사용한다. 배율에는 서버 태그·레벨·보유골드·스토리 개방 및 현재 시간이 들어간다. 활성 `TaskGoldCostConfig`, `StoryUpdate`, `general` 값은 현재 자료에서 확보하지 못했다. 따라서 기본 골드 그래프를 현행 유저의 실지불 비용·소요시간으로 제시하지 않는다.

fire3,939행은 별도 도입부/스토리 변형이다. 기본4,277행과 합산해8천여 개의 연속 과제로 만들지 않는다.

## 주문 난이도와 동적 조정

일반 생성의 흐름은 슬롯/생성기/아이템 해금·재고·중복·직전주문 필터 → 현재상태 가중 → 첫 일치 난이도 필터 → 후보단계 선택 → 최종 요구개수 선택 → 보상·예산/CD다. 고정/복귀/튜토리얼/활동 주문 등의 선행 생성 경로도 있다.

- 기본 일반 정책5유형의 최종 요구개수는 **1개50 / 2개50 / 3개0** 가중치다. Third 후보범위가 있다는 이유로3개 요구가 출현한다고 해석하지 않는다. 다른 정책에서 ItemAmounts가 없으면 계정Level별 공통 개수표를 사용한다.
- 필터의 단계는 `DifficultyLevel`이 있으면 그 값이고 없으면 체인 단계다. 기본74아이템 중18행이 별도 DifficultyLevel을 가진다. `Price`, `DiffScore`, 체인 단계는 서로 다른 축이다.
- 일반 슬롯 완료 시 요구아이템 DiffScore를 누적하고 로컬시각2AM에 초기화한다. 기본Type3은 Lv36–60의2000/2001, Lv61+의2500/2501 경계에서 요구 하한 등이 오른다. Type4도 자체 레벨/점수 경계를 가진다.
- 재고 기반 가중치100/1000/10000 및 서버 `OrderDiffDynamic`에 따른10^n과, `DynamicFirstMax`류의 체인 한정 단계확장은 서로 다른 장치다.
- 반복선택 가중치 감소·직전 주문 회피·다른 주문이 없을 때 Type2 쿨다운 우회·Baseline 재고소진·복귀무료 주문 등 완화 경로도 있다.
- `RefreshTime`은 예산/쿨다운 설정이다. Type1은 공유5점 예산이므로 매 주문마다3600초를 기다린다는 뜻이 아니다. 실제 생성간격은 주문/포인트·예외·활동에 따라 달라진다.

월결제 범위를 비교하는 코드는 있으나 확보한15정책의356필터에는 결제 경계값이0건이다. 현재 과금자에게 더 어려운 주문을 준다고 단정할 근거는 없다. `hard`, `lessitem`, `dynamic` 등은 출하 변형이며 현재 계정의 실험군 배정을 뜻하지 않는다.

15정책·126유형행 × 계정Lv1–300 × DiffScore0/2000/2001/2500/2501의 **189,000조건**에서 필터는 정확히1개씩 일치했다. 이는 선언범위의 정적 검사이며 실제 주문확률 검증이 아니다.

고정 주문16개, 특수 주문6개와 과제Trigger·요구·생성체인을 따로 정리했다. 분기 주문표1행이 있어도 해당 생성함수는false이며, 기본 신규아이템 주문표는 비어 있고 테스트표만15행이다. 선언·활성·테스트를 같은 모집단으로 합치지 않는다.

## 보드·생성기와 이벤트 설계

원문 메인판은7×9=63칸이고 상자60·거미줄1·노출아이템2로 빈칸이 없다. 초반 인접합성으로 상자를 벗기며104생성기에 도달하는 구조는 입력학습과 공간확보를 연결한다. `ProtectLevel`을 계정레벨별 상자해금으로 해석하지 않는다.

기본163생성기의 원본 선택종류는 Fixed97·Decremental54·OrderItem6·ChestCustom1·Smart5다. 에너지소비51·자동5행이며, 묶음회복2–21,600초·저장회복30–43,200초 범위는 해당 필드가 있는54행에서 집계했다. 고정/소진형 덱을 무한 IID추첨으로 계산하면 분산·시간 예측이 달라진다. 104의80묶음/240저장/2초/30초를 모든 생성기로 일반화하지 않는다.

동일타입2→1·기본1단계만 공급되는 제한에서 단계L은2^(L−1)기본단위다. 실제 에너지/시간에는 높은 단계드롭·스마트산출·기존재고·도구·부스터·공급보상·칸 여유가 개입한다.

66배치 표는 메인1·Adventure10·Break2·Dig1·Dig2 2·Farmboard5·Multiboards32·Pureboard4·Stickerboard9다. Multiboards의판순서와 Stickerboard총단계 등은 서버 설정이 조립하므로 로컬파일32개/9개를 현재 시즌 단계수로 읽지 않는다. MapExplore도 별도 탐색/비용 루프다.

PureBoard `SetLevel`은 합성계열 최고단계·안개개방의 진행축이다. 이벤트 `BoostUnlock.unLockMainLevel`도 이름과 달리 소비자는 이벤트MergeLineLevel과 비교한다. dogpark의2×/4×/8× 기본 기준9/10/11과 변형7/10/12는 계정레벨이 아니다. 안개는 체인단계 또는 특정열쇠 개수로 열리는 등 콘텐츠마다 설계가 다르다.

## BM 연결과 신규 게임 적용

에너지 부족은 충전/상황형 오퍼, 생성기 대기는 시간도구·NoCD, 높은 요구는 특정아이템/버블·단계도구, 보드포화는 보관함·판매·납품, 기간수집은 패스/팩/번들과 연결된다. 이 구조는 상품노출의 맥락이며 매출효과의 측정결과가 아니다.

신규 게임은 다음 축을 별도 데이터로 관리하는 것이 적절하다.

1. 계정XP·승급보상·기능해금과 스토리비용/보상을 분리한다.
2. 합성그래프·생성기 공급/회복·에너지·보드공간을 주문수요와 함께 분석한다.
3. 주문의 가격·DiffScore·난이도단계·요구개수·후보필터·동적정책을 별도로 조정한다.
4. 이벤트는 전용level·토큰·기간·스테이지를 계정레벨과 분리한다.
5. 출시구간을 확정한 뒤 그 구간의 재화수지·장기대기·포화·복귀·다중활동을 여러 시드와 플레이로 검증한다.

현재 자료로 정적 설계와 비교표는 작성 가능하다. 현재 계정의 정책/활동배정, 실제 보정비용, 전체300레벨 자유진행, 체류·전환·매출은 미확인이다. 기존 고정100개 체크리스트의 구현 잔여/원작 검증/운영값 미확보/기획 결정에 유지한다.

## 재현·근거

로컬 폴더 `analysis/difficulty-level-design-20261105/`의 `progress-findings`, `orders-findings`, `content-findings` 문서/JSON과 검증결과가 원자료다. `build-study.py`는 출처파일 해시를 확인하고 공개용 지표·범위·정책선택 데이터를 만든다. 공개 JSON의 `sources`에는 원본 경로·행·SHA, `auditReports`에는 로컬 분석보고서 해시가 있다. REA 세션 상태를 확인하고 기존 복원자료를 재사용했으며 새 REA Evidence ID를 임의로 만들지 않았다. 원본 전체Lua·APK·운영/개인 데이터를 게시하지 않는다.
