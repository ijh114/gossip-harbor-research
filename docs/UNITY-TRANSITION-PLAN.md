# Unity 중심 개발 전환 계획

기준일: 2026-10-30. 이 문서는 계획이며 Unity 구현 완료 보고가 아니다. 고정 작업 ID와 완료 판정은 [MASTER-CHECKLIST.md](MASTER-CHECKLIST.md)를 유지한다. 웹의 구현·모델 검사 통과와 원작 게임·Unity 기기 실행 검증은 각각 별도로 기록한다.

**방향:** 게임 개발·플레이·씬/UI·애니메이션 검증의 기준을 Unity로 옮긴다. 웹은 근거·비교 자료·BM 분석·제작 리소스 발주·진행 장부를 유지한다. 같은 게임 기능을 웹과 Unity에서 계속 이중 개발하지 않는다. 기존 웹 모델은 C# 이식의 입력/출력 대조 자료로 보존한다.

**현재 출발점:** 로컬에 Unity6000.3.21f1이 설치돼 있다. 기존 `unity/Packages/com.harbor.research.rules`는 Unity6000.3용 초기 UPM 패키지다. 에너지/BM 규칙과 과거2,701개 JS/C# 대조가 있으나, `BoardRules.cs`는 bread/tea를 사용하는 초기 독립 실험이다. 최신552타입·생성기·주문·도구·활동 전체를 이미 이식한 것으로 계산하지 않는다. 기존 패키지를 버리거나 원작 클래스 구조에 맞춰 이름만 바꾸는 방식도 사용하지 않는다.

**참고할 구조:** 가십하버의 플레이 상태·콘텐츠 종류·해금/재화/BM 연결·화면 동선·필수 UI 역할을 대응시킨다. 아래 씬 이름·패키지 경계는 새 프로젝트의 제안이며 원작 Scene 목록이라고 주장하지 않는다. 복원된 Lua/C#를 실행 코드로 복사하지 않고 독립 C# 구현과 새 데이터 계약을 작성한다.

이번 요청의 목표는 전체 시스템·콘텐츠 유형의 대응 구조다. 대표 이벤트 하나는 공통 구조를 검증할 첫 구현이며, 그 하나만을 전체 범위로 정하지 않는다. 시즌·맵·스토리의 실제 제작 분량과 모든 역대 운영 변형은 구조의 지원 여부와 별도로 수량을 관리한다. 기존 웹 저장소와 별도의 Unity 게임 저장소를 사용하고, 원작 분석 자료 보관소는 제작 자산팩과 분리한다.

**개발 시작 전 확정할 분석 패키지:**

- 시스템/콘텐츠 대응표: 각 기능의 상태·입력·출력·실패·타이머·잠금·재접속·보상 목적지·참조 데이터·근거와 미확정 조건. 추가 활동도 전부 목록에 남기고 MVP/출시/후속으로 구분한다.
- 화면/프리팹 계약: 로딩·타이틀·튜토리얼·메인 맵·퍼즐·과제/보상·장식·상점·패스·앨범·대표 이벤트의 진입/복귀, modal stack, Safe Area, 마스크, 한국어 폰트, 입력 차단 소유자.
- 경제/BM 계약: 재화의 유일한 원장, 주문/과제 보상, 에너지·생성/가속·버블·보관함 비용, 상점 갱신/오퍼 우선순위, 종료/반환·중복 수령과 실패 롤백. BM은 표시되는 화면만으로 완료 판정하지 않는다.
- 데이터/자산 계약: 안정적인 ID, schema/콘텐츠 버전, 교차 참조, 기본/누락 처리, atlas·피벗·9-slice·애니메이션 시작/루프/종료·효과음 cue·메모리 예산·제작 발주서.
- 대조 시나리오: 같은 초기 상태·시각·난수·명령으로 JS/C#의 상태·거절 이유·소비/보상·UID·저장 결과를 비교. 웹 결과도 APK 근거와 어긋나면 웹을 무조건 정답으로 사용하지 않는다.

이 패키지는 모든 원작 분석이100% 끝나야만 닫히는 문서가 아니다. 잘못된 재화 지급·저장·입력/씬 구조를 만들 수 있는 미해석은 해당 모듈 착수 전에 해결한다. 실제 서버 가격/시즌/확률, 원작 청취·동적 카메라/최종 shader, WestSearch3 호출·property_bubble_1·CG 전체 native 흐름처럼 현재 근거가 부족한 내용은 명시적으로 보류하거나 별도 설계값을 사용한다. 설계값을 원작 확인값으로 바꾸지 않는다. 후반 변형의 미확정 때문에 기본 퍼즐 개발 전체를 대기시키지 않는다.

**제안 프로젝트 구조:**

```text
UnityGame/
  Assets/Game/
    Scenes/           Boot, Main, Activity, Preview
    Presentation/     지도·퍼즐·UI·캐릭터·VFX·Audio 어댑터
    Editor/           보드/주문/과제/BM/튜토리얼·자산 검수 도구
    Content/          ReferenceProfile, GameThemeA, GameThemeB
  Packages/
    com.harbor.game.core/        순수 C# 상태·명령·경제·난수/시각 계약
    com.harbor.game.features/    주문·과제·공장·튜토리얼·활동·컬렉션·Skin
    com.harbor.game.persistence/ 저장 버전·복구·이전·영수증
    com.harbor.game.platform/    설정·시간·결제/광고·계정 어댑터
  Tests/              EditMode, PlayMode, JS/C# 대조, 기기 시나리오
```

- Boot는 앱 서비스와 저장/콘텐츠 검사를 유지한다. Main은 맵·퍼즐·공통 UI를 상태에 따라 전환한다. Activity는 별도 보드·이벤트 영역을 필요할 때 로드한다. Preview는 그래픽/연출 담당자가 에디터에서 바로 검사하는 개발용 공간이다. 레벨·팝업·장식 선택마다 Scene을 늘리지 않는다.
- 도메인 규칙은 MonoBehaviour·GameObject·UI·네트워크와 분리한다. 시간·난수·저장·운영 설정·가격은 명시 인터페이스로 주입한다. UI 애니메이션 종료 콜백이 재화를 임의로 확정하지 않게 한다.
- 시스템별 assembly definition과 명시 의존 관계를 두고, 화면의 Presenter와 재사용 가능한 prefab/view를 분리한다. 모달/뒤로가기·입력 잠금·취소·구독 해제·리소스 해제를 공통 수명주기로 관리한다.
- 안정적인 논리 ID를 ThemePack의 Sprite/Prefab/Audio/Animation에 결합한다. 애니메이션은 Animator/Spine 등 특정 구현을 감춘 어댑터로 교체한다. 원작 리소스 이름이나 경로를 게임 로직의 조건으로 쓰지 않는다.
- 데이터의 Git 관리 원본은 하나로 정한다. JSON/CSV와 ScriptableObject를 사람이 각각 수정하는 이중 원본을 만들지 않는다. 에디터는 같은 데이터에 대한 편집·미리보기·검증을 제공한다.
- 저장은 schema/콘텐츠 버전과 프로필 ID를 포함한다. 임시 파일→원자적 교체·이전 백업·마이그레이션·손상 보존을 구현한다. 구매/보상은 고유 거래 ID와 영수증으로 중복 지급을 차단한다.
- 풀링·atlas·Canvas 분리·변경 이벤트 기반 갱신·비동기 로딩/취소·Addressables 해제를 적용하고 기기에서 측정한다. 매 아이템 Update·매 프레임 레이아웃 재빌드·전역 무제한 이벤트 버스·보드63칸에 불필요한 ECS를 기본 구조로 넣지 않는다.

**권장 기술 기준:** 설치된 Unity6.3 LTS를 출발점으로 고정하고 호환성 smoke test 후 정확한 패치/패키지 버전을 잠근다. 런타임 UI는 프리팹·키프레임 연출을 다루기 쉬운 uGUI/TextMeshPro, 에디터 관리 도구는 UI Toolkit을 우선 검토한다. 맵·2D 캐릭터·UI의 작은 샘플로 렌더 파이프라인·마스크·정렬·모바일 성능을 비교한 뒤 URP 구성을 확정한다. Addressables는 먼저 로컬 콘텐츠로 검증하고 이후 콘텐츠 버전·원격 catalog·롤백 운영을 연결한다. 자동 패치 업그레이드나 패키지 무작위 추가는 하지 않는다.

단계3의 실제 플레이 한 사이클은 최종 범위를 축소하는 것이 아니라 구조를 검증하는 첫 마일스톤이다. 이후 최종 선택한 시스템과 콘텐츠를 같은 체크리스트에서 채운다. 각 단계는 코드 작성·Editor 실행·기기 검증·원작 대조를 따로 표시하고, 구현 완료 후 새 이름의 필수 보강 작업을 만들어 완료 기준을 미루지 않는다.

**BM 우선 검증표:** 최초 노출, 레벨/진행/재화 조건, 에너지 부족/생성 실패, 창 닫힘/재접속 후 재노출, cooldown/일 경계, 오퍼 우선순위/동시 노출 억제, 구매 성공/실패/복원·영수증, 시즌 시작/종료/반환, 팩 확률·중복/교환·패스 보상, 분석 로그를 각각 테스트한다. 테스트용 가격·상품·일정은 운영 프로필에 명시하며 원작 계정의 실제 값이라고 표시하지 않는다. 결제/광고는 먼저 sandbox/stub로 검증하고 실제 서비스 연결·서버 검증·계정 동기화는 별도 통과 조건을 둔다.

**‘교체하면 돌아가는 템플릿’의 구체적 기준:** ThemePack은 이미지·맵·캐릭터·UI·VFX·오디오·폰트를, TutorialPack은 대상 ID·조건·문구/손동작·허용 입력·강제 생성·지연/분기·완료/복구를, ContentPack은 아이템/주문/과제/스토리/패스·앨범/이벤트를, EconomyProfile은 가격·재화·확률·일정/보상을 가진다. 기본 프로필은 완결된 샘플을 제공한다. 튜토리얼·그림만 교체해도 샘플은 실행돼야 하지만, 새 게임의 실제 콘텐츠와 BM 변경은 해당 데이터도 교체해야 한다. 새로운 규칙/게임 모드는 명시적인 기능 확장에 해당한다.

마지막 시험은 개발자가 코드에 새 리소스 경로를 하드코딩하는 방식이 아니라 두 번째 테마팩만으로 진행한다. 검증기는 누락 ID·잘못된 보상·단절된 체인·튜토리얼 교착·미매핑 소리/애니메이션·과도한 메모리를 빌드 전에 보고해야 한다. 기존 테마 저장을 새 테마에 조용히 덮어쓰지 않는다.
